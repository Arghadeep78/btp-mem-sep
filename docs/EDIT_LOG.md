# Edit Log

The complete list of **edits made to files in this project**: files created, modified or deleted. Applying the rows **in ID order** takes an old file to the current state; applying their **Undo** in reverse ID order takes the current file back.

## Rules
1. **Only real file edits.** Don't log analysis, runs, scratch copies, tests or blocked/failed attempts.
2. **One row per file per edit.** If one change touches three files, write three rows with the same Change ID.
3. **Replayable both ways:** every row says exactly what changed and how to undo it.
   - Simulation and model files (`.bkp`, `.acmf`, `.ATMLZ`): give the exact text/values before → after and the location (block, line), so the edit can be redone or undone by hand.
   - Docs: give the section and a summary. The exact text change is the git diff of the commit listed in **Commit**.
4. **Order = ID order.** IDs are assigned in the order edits were applied. Timestamps are informational; some early ones are approximate.
5. **Append only.** Never edit past rows. When an edit is undone, add a new row with Action = `undo` that names the Change ID it reverses.
6. Timestamps are local (IST, +05:30), `YYYY-MM-DD HH:MM`. **By** is `user`, `claude@win` or `claude@mac`. **Commit** shows the commit containing the edit, or `—` if uncommitted.
